# Supabase for Postgres and realtime push

We considered hand-rolled WebSockets, but Vercel's serverless platform cannot host persistent WebSocket servers, making the originally imagined "Next.js + Postgres + WebSockets on Vercel" impossible as described. We decided to use Supabase, which provides managed Postgres plus its Realtime service, giving ~1s push latency for release events with no extra vendor beyond the database we already need. Release-event volume (a handful per hour per case) makes any realtime backend sufficient; Supabase minimizes moving parts. Alternatives rejected: Pusher/Ably (second vendor alongside a separate Postgres), SSE hand-rolled on Vercel (fragile under serverless: timeouts, cold starts, no cross-instance pub/sub), self-hosted Node server (drops Vercel, ops burden).
