# Cases reference case-type findings; no snapshotting

When a case starts from a case type, its findings are referenced, not copied into the run. Editing or removing a type finding therefore retroactively affects every past run's viewer. We accepted this because students do not review cases outside the classroom and findings rarely change once authored. The original V1 model had no type editor and treated mutations as deliberate developer actions; ADR-0007 records the later introduction of an admin editor and the deletion safeguards that came with it. Rejected alternative: snapshotting findings into each run for immutable history — unnecessary given the above, at the cost of duplicate storage and sync questions.
